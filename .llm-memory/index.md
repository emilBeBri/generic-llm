# .llm-memory index

Persistent project knowledge for `generic-llm` (the `gllm` CLI).

## Conventions
- [CONVENTIONS-schemas-and-instructions.md](CONVENTIONS-schemas-and-instructions.md) — Two-tier library layout (bundled `data/` + future `~/.config/gllm/` overlay), the all-required + empty-string-sentinel schema convention (for OpenAI strict-mode portability), and the instruction-authoring patterns.
- [CONVENTIONS-multi-provider-routing.md](CONVENTIONS-multi-provider-routing.md) — the adapter side: when to subclass `OpenAIProvider`, when to go standalone, and when the generic `openai_compat` adapter covers a host for free; plus the Anthropic adaptive-vs-budget thinking dialects. The pre-2026-07-29 substring routing table lives here too, marked superseded.
- [CONVENTIONS-file-attachments.md](CONVENTIONS-file-attachments.md) — `-f PATH` (with `-` for stdin, process substitution for free), the `Attachment` domain type, and the native-or-fail capability matrix.
- [CONVENTIONS-zai-glm-adapter.md](CONVENTIONS-zai-glm-adapter.md) — Z.AI/GLM provider (`glm-*` → `zai`, OpenAI Chat @ api.z.ai): standalone NOT an OpenAIProvider subclass (else routed to Responses API GLM can't speak), `thinking`+`reasoning_effort` (glm-5.2 only), vision-model split now declarative via `ModelCaps` (so `supports_image` takes a model), json_object-only (`--schema` refused), listable via `models.list()`.
- [CONVENTIONS-kimi-adapter.md](CONVENTIONS-kimi-adapter.md) — Moonshot Kimi provider (`kimi-*` → `kimi`, OpenAI Chat @ api.moonshot.ai): standalone family-specific reasoning controls, image input, top-level cached-token usage, and no multi-turn reasoning replay.
- [CONVENTIONS-porting-adapters-from-reference.md](CONVENTIONS-porting-adapters-from-reference.md) — how to port a provider adapter from bebri-chat (the reference): reshape not copy (mirror protocol facts; drop tools/web-search/registry; deviate to gllm's fail-loud + trust-the-docs house rules). The process rule: every port must read the reference + provider docs concretely AND **ask the user** if this reshape is right for that provider (noting it's the established pattern). GLM is the first worked example.
- [CONVENTIONS-usage-cost-emission.md](CONVENTIONS-usage-cost-emission.md) — `--usage` emits one `gllm-usage {json}` line to stderr (tokens/cache/reasoning + provider-verbatim `usage_raw` + derived `cost_usd`/`priced_as`); per-provider mappers in `usage.py` normalise usage at the source; `pricing.py` converts to USD from the llm-price-tracker book (offline, editable path dep) with provider-aware billing, overlaid by `data/prices.json` (keyed by registry key; fills the ~65 models the book can't price — GLM, Groq, Regolo, Azure -dev, codex/chat aliases).
- [CONVENTIONS-one-shot-workload-no-cache.md](CONVENTIONS-one-shot-workload-no-cache.md) — gllm calls are ONE-OFF shots and never request caching, so cache-hit rates are noise in a gllm model comparison and the peak/off-peak swing lands at full weight. Carries the measured no-cache cost table, the Gemini bills-thinking-on-top asymmetry, DeepSeek's missing `low` rung, and why a model verdict does NOT port between gllm and bebri-chat.

## Architecture / gotchas
- [ADR-provider-model-axis.md](ADR-provider-model-axis.md) — **models and providers are two axes.** `provider_for` is a `MODELS` registry lookup, never a name guess (the lab that trained a model ≠ the host that serves it: `groq:openai/gpt-oss-120b`, `regolo:glm5.2-beta`). `ProviderSpec.adapter_kind` is a string so config never imports adapters; unknown names warn and still run; `wire_id` strips host namespaces; WORK reads `azure_alias` instead of appending `-dev`. `tests/test_registry.py` is what stops the two dicts drifting.
- [ADR-reasoning-effort-ladder.md](ADR-reasoning-effort-ladder.md) — the `-r/--reasoning low/medium/high/xhigh` knob: **four fixed rungs, NORMALISED onto each model's own vocabulary** (`ModelCaps.native_efforts`) by `reasoning.resolve_effort`. `xhigh` always means "the most this model has" (`max` on DeepSeek/GLM/Claude-5/GPT-5.6); `-r low` is always the cheapest available and never silently upgraded. Remaps are announced on stderr, silenced by `-q`. A briefly-added `max` rung was removed — the ladder must stay stable for scripts. bebri-chat deliberately does the opposite.
- [GOTCHA-grok-per-model-effort-vocabulary.md](GOTCHA-grok-per-model-effort-vocabulary.md) — xAI's `reasoning_effort` support is per-model and the docs describe it wrongly: grok-4.5/4.3 take `xhigh`, multi-agent takes `max` (= agent count), and `grok-build-0.1` / both `grok-4.20-0309-*reasoning` variants 400 on the parameter despite their pages saying "Reasoning: Yes". Probed live 2026-07-29; gllm and bebri-chat each had half of it wrong.
- [GOTCHA-azure-foundry-constraints.md](GOTCHA-azure-foundry-constraints.md) — Azure Foundry specifics: it DOES expose `output_config` (`effort` verified, `format` an unverified native attempt — corrected 2026-06-17), endpoint rewriting, and the `WORK=1`/`WORK_ENV` direct-vs-Azure routing toggle (`effective_model` reads `ModelSpec.azure_alias`; an unaliased model falls back to `<name>-dev` with a warning, because deployment inventory is live data the registry can't know).
- [GOTCHA-jail-uv-venv-artifactory.md](GOTCHA-jail-uv-venv-artifactory.md) — running the test suite in the claude-jail: gllm's deps are pure public PyPI (zero Artifactory), but `uv run`/`uv sync` chase uv's Artifactory default index (host cache cruft), hit 401, and **delete `.venv`**. Fix: `PYTEST_ADDOPTS= .venv/bin/python -m pytest` (never `uv run` here). Also covers reaching the `llm-price-tracker` path dep via a `symlinks/` entry (the jail binds the target at its ORIGINAL host path, which is what the editable `.pth` needs), `uv lock --offline` as the safe relock now that no PyPI dep remains, and why `pytest` needs `testpaths` once sibling repos are symlinked in.
- [ADR-base-url-env-override.md](ADR-base-url-env-override.md) — `GLLM_BASE_URL_<TAG>` redirects any provider's endpoint through `config.resolve_base_url` (generic name beats the legacy `ZAI_BASE_URL`; blank ignored). Wired into **every** provider now — openai/anthropic/gemini each kept the variable their SDK used to read (`OPENAI_BASE_URL`, `ANTHROPIC_BASE_URL`, `GOOGLE_GEMINI_BASE_URL`) as `legacy_env`, because those are exactly what the broker sets. Keep API version segments OUT of the base URL or every override 404s. Consumer: the claude-jail `llm-key-broker.py` loopback proxy — note a host-side key rotation only reaches a jailed session on relaunch.
- [ADR-output-budget-resolution.md](ADR-output-budget-resolution.md) — `--max-tokens` defaults to `None` and `cli._resolve_max_tokens` decides the budget once; the nine per-adapter `max(request.max_tokens, 16000)` floors are gone. gllm's own guess is overridable, an explicit value is honoured (with a warning if cramped), and only an API-enforced minimum (Anthropic's `budget_tokens < max_tokens`) refuses. `ModelSpec.max_output` holds documented ceilings for 27 rows; `None` means unsourced, not unlimited. Also: the clamp keeping input + output inside the context window (measured on GLM, enforced to the token), that `--usage` now reports what was **sent**, and a **correction** — `~/source-docs/` is NOT corrupt; that was a tool-output display artefact, so ~100 rows were left unsourced for no reason.
- [ADR-stdlib-http-transport.md](ADR-stdlib-http-transport.md) — the vendor SDKs (`openai`/`anthropic`/`google-genai`) are being replaced by `gllm._http` (stdlib `http.client`) — **DONE, all ten adapters; pyproject declares no vendor SDK at all.** `import anthropic` built 462 pydantic classes / 1247 modules for ~0.9 s that lazy-importing cannot recover, and adapters already hand-built the request dict. 0.111–0.124 s per provider now, from 0.88–1.46 s. `wrap`/`Obj` kept response parsing and all of `gllm.usage` unchanged. Traps: `extra_body` was never a wire concept; `output_text` is an SDK convenience; Gemini renamed fields by more than case (`supported_actions` → `supportedGenerationMethods` returned an EMPTY catalog, not an error); Anthropic's 10-minute non-streaming ceiling makes SSE mandatory. Anthropic + both Azure adapters are unit-tested only.
- [GOTCHA-stop-reasons-that-mean-no-answer.md](GOTCHA-stop-reasons-that-mean-no-answer.md) — the three ways a 200 yields output nobody can trust: budget exhausted (warn, keep the text — including Gemini's MAX_TOKENS *enum*, whose str() matches nothing), `refusal` (raise; no text block exists, so gllm otherwise prints a blank line and exits 0), and `pause_turn`, which is unhandled. Plus the full Anthropic stop_reason enum. Two of the three were found by reading bebri-chat, not by testing.
- [ADR-model-listing-live-probe.md](ADR-model-listing-live-probe.md) — there is NO model allowlist (adapters forward the name verbatim, so hand-maintained catalogs drift and lie — `gemini-3-flash-preview` was wrongly called "retired"); `gllm --models [PROVIDER]` queries only configured providers and prints greppable text-gen `provider<TAB>key` rows. WORK substitutes Foundry for direct Anthropic/OpenAI; Azure uses explicit registered `-dev` deployments because its inference APIs cannot enumerate deployments.

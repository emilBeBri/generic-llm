- [CONVENTIONS-multi-provider-routing.md](CONVENTIONS-multi-provider-routing.md) — the adapter side: when to subclass `OpenAIProvider`, when to go standalone, and when the generic `openai_compat` adapter covers a host for free; plus the Anthropic adaptive-vs-budget thinking dialects. The pre-2026-07-29 substring routing table lives here too, marked superseded.
- [CONVENTIONS-file-attachments.md](CONVENTIONS-file-attachments.md) — `-f PATH` (with `-` for stdin, process substitution for free), the `Attachment` domain type, and the native-or-fail capability matrix.
- [CONVENTIONS-zai-glm-adapter.md](CONVENTIONS-zai-glm-adapter.md) — Z.AI/GLM provider (`glm-*` → `zai`, OpenAI Chat @ api.z.ai): standalone NOT an OpenAIProvider subclass (else routed to Responses API GLM can't speak), `thinking`+`reasoning_effort` (glm-5.2 only), vision-model split now declarative via `ModelCaps` (so `supports_image` takes a model), json_object-only (`--schema` refused), listable via `models.list()`.
- [CONVENTIONS-porting-adapters-from-reference.md](CONVENTIONS-porting-adapters-from-reference.md) — how to port a provider adapter from bebri-chat (the reference): reshape not copy (mirror protocol facts; drop tools/web-search/registry; deviate to gllm's fail-loud + trust-the-docs house rules). The process rule: every port must read the reference + provider docs concretely AND **ask the user** if this reshape is right for that provider (noting it's the established pattern). GLM is the first worked example.
- [CONVENTIONS-usage-cost-emission.md](CONVENTIONS-usage-cost-emission.md) — `--usage` emits one `gllm-usage {json}` line to stderr (tokens/cache/reasoning + provider-verbatim `usage_raw` + derived `cost_usd`/`priced_as`); per-provider mappers in `usage.py` normalise usage at the source; `pricing.py` converts to USD from the 24h-cached llm-prices.com feed with provider-aware billing, overlaid by `data/prices.json` (keyed by registry key; fills the ~70 models the feed can't price — GLM, Groq, Regolo, Azure, and the newest frontier rows).

## Architecture / gotchas
- [ADR-provider-model-axis.md](ADR-provider-model-axis.md) — **models and providers are two axes.** `provider_for` is a `MODELS` registry lookup, never a name guess (the lab that trained a model ≠ the host that serves it: `groq:openai/gpt-oss-120b`, `regolo:glm5.2-beta`). `ProviderSpec.adapter_kind` is a string so config never imports adapters; unknown names warn and still run; `wire_id` strips host namespaces; WORK reads `azure_alias` instead of appending `-dev`. `tests/test_registry.py` is what stops the two dicts drifting.
- [ADR-reasoning-effort-ladder.md](ADR-reasoning-effort-ladder.md) — the `-r/--reasoning low/medium/high/xhigh` knob: **four fixed rungs, NORMALISED onto each model's own vocabulary** (`ModelCaps.native_efforts`) by `reasoning.resolve_effort`. `xhigh` always means "the most this model has" (`max` on DeepSeek/GLM/Claude-5/GPT-5.6); `-r low` is always the cheapest available and never silently upgraded. Remaps are announced on stderr, silenced by `-q`. A briefly-added `max` rung was removed — the ladder must stay stable for scripts. bebri-chat deliberately does the opposite.
- [GOTCHA-grok-per-model-effort-vocabulary.md](GOTCHA-grok-per-model-effort-vocabulary.md) — xAI's `reasoning_effort` support is per-model and the docs describe it wrongly: grok-4.5/4.3 take `xhigh`, multi-agent takes `max` (= agent count), and `grok-build-0.1` / both `grok-4.20-0309-*reasoning` variants 400 on the parameter despite their pages saying "Reasoning: Yes". Probed live 2026-07-29; gllm and bebri-chat each had half of it wrong.
- [GOTCHA-azure-foundry-constraints.md](GOTCHA-azure-foundry-constraints.md) — Azure Foundry specifics: it DOES expose `output_config` (`effort` verified, `format` an unverified native attempt — corrected 2026-06-17), endpoint rewriting, and the `WORK=1`/`WORK_ENV` direct-vs-Azure routing toggle (`effective_model` reads `ModelSpec.azure_alias`; an unaliased model falls back to `<name>-dev` with a warning, because deployment inventory is live data the registry can't know).
- [ADR-model-listing-live-probe.md](ADR-model-listing-live-probe.md) — there is NO model allowlist (adapters forward the name verbatim, so hand-maintained catalogs drift and lie — `gemini-3-flash-preview` was wrongly called "retired"); `gllm --models [PROVIDER]` probes each provider's live `models.list()` and prints greppable text-gen `provider<TAB>key` rows (loud-skip on no key, Azure excluded as deployment-scoped). Still true after the 2026-07-29 registry: it says how to *drive* a model, `--models` says what *exists*.
